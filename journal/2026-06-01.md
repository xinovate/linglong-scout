## 完成记录

### 1 OpenGithubs 描述解析 bug 修复

**问题**：OpenGithubs 返回的 markdown 中，每个 repo 有 `<h3>` 详情段落含 `项目描述` 字段。原实现用 `re.DOTALL` 正则 `rf"{escaped}.*?项目描述[：:]\s*(.+?)(?:\n|$)"` 匹配描述，导致跨段匹配——rank 2+ 的 repo 错误地拿到前一个 repo 的描述。

**方案**：
- 新增 `_extract_detail_descriptions(md)` 函数：按 `<h3>` 标签 split，逐段匹配 repo URL + `项目描述`，避免跨段污染
- `_github_trending()` 中替换旧的逐 repo 正则为批量描述提取
- 空描述时保留 repo name（表格仍可渲染）

**Commit**: `293870f`

### 2 Docker 环境 GITHUB_TOKEN 支持

**问题**：Docker 容器（`python:3.12-slim`）无 `gh` CLI，`_github_headers()` 调用 `gh auth token` 失败，GitHub API 仅 60 req/hr 限流，OpenGithubs 请求被限流导致 fallback 到 wangchujiang 源。

**方案**：
- `_github_headers()` 改为 async，优先检查 `GITHUB_TOKEN`/`GH_TOKEN` 环境变量，失败才 fallback 到 `gh auth token`
- `docker-compose.yml` 新增 `GITHUB_TOKEN=${GITHUB_TOKEN:-}` 环境变量透传
- 服务器 `.env` 配置实际 token，认证后 5000 req/hr

### 3 RSS-first 采集策略重构

**背景**：OpenClaw 反馈 `fetch_raw` 返回的原始数据中 SearXNG 结果噪音严重——字典释义、消费品、电竞内容混入 AI 专题。63 个宽泛关键词产生 ~260 条结果，信噪比极低。用户明确拒绝规则过滤方案（"无底洞"）。

**策略转向**：
- **RSS 为主力**（人工编辑筛选，天然高信噪比）+ **SearXNG 为实体级精准补充**（只查具体人名/公司名/产品名）
- 总数据量从 ~493 条降到 ~210 条，信噪比大幅提升

**改动范围**：
- `.scout.yml`：RSS 11→14 源，SearXNG 63→20 关键词
- `.scout.example.yml`：同步
- `prompts/morning_brief.md`：强调 RSS 为信息主力
- `docs/design/`：数据源文档 + 总览文档更新
- `docker-compose.yml`：GITHUB_TOKEN 环境变量

**Commit**: `293870f`

### 7 服务器部署与调试
