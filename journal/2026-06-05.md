## 任务详情

### 任务 1：OpenClaw MCP 连接失败排查

**问题**：OpenClaw 报"linglong_generate_brief() 工具不可用"，仅看到 linglong-knowledge 工具。

**排查**：
- Scout 容器 healthy，本地 `127.0.0.1:9900` 正常响应
- Cloudflare Tunnel 可达，外部 `https://open.linglong.wiki/mcp/scout` 返回 401（认证拦截正常）
- Token `ll-scout:xinovate:8ulqnugjof2qb7ryfs` 在 Redis 中状态 active
- 完整 MCP 流程测试（initialize → tools/list）成功，6 个工具全部返回
- Tunnel 日志有 `stream canceled by remote with error code 0` 错误

**结论**：服务端完全正常，问题在 OpenClaw 客户端对 MCP streamable-http 协议的支持（需 `Accept: application/json, text/event-stream` 头 + SSE 解析 + session 管理）。

### 任务 2：早报开源趋势改为日榜 TOP 8

**问题**：原 prompt 日/周/月混合，LLM 会混排数据且编造增长数字（如 Understand-Anything 日增 +1,032 被写成周增 +24,785）。

**方案**：改为仅取日增长 TOP 8，表格格式精简为 `项目 | 日增长 | 总 Stars | 简介 | 链接`，明确约束"数字必须与原始数据完全一致，不得编造"。

### 任务 3：关键人物/行业要闻增加来源溯源列

**问题**：早报信息无法溯源，读者无法验证信息来源。

**方案**：两表各增加"来源"列，格式 `[媒体名](url)`。规则：从原始数据提取真实 URL；提取不到则只写媒体名不加超链；禁止编造 URL。

### 任务 4：GitHub 日榜采集数不足 TOP 8

**问题**：开源趋势只有 4 条日增长，不足 TOP 8。原因：`github_trending_limits.daily` 配置为 5（默认）/ 4（服务器），OpenGithubs 当天数据刚好只返回 4 条。

**方案**：config.py 默认值、`.scout.example.yml`、`.scout.yml` 统一改为 `daily: 10`。另外发现 `generate_brief` 复用 raw data 缓存，清 brief 缓存后还需清 raw data 缓存才能触发重新采集。

### 任务 5：服务器 .scout.yml 超级个体关键词去重

**问题**：`search_queries` 中"超级个体/一人公司"关键词组重复了 4 次，导致同样的 5 个关键词发 4 次 SearXNG 请求（20 次重复）。

**方案**：删除 3 个重复组，保留 1 份。8 组 → 5 组。

### 任务 6：服务器 .scout.yml 恢复

**问题**：用 Python yaml.dump 修改配置时，服务器 Python 3.6 的 yaml 库兼容问题导致文件被清空（0 字节）。

**方案**：通过 SSH heredoc 直接写入完整配置文件恢复。

### 任务 7：服务器 MCP 421 Misdirected Request 修复

**问题**：所有 MCP 请求返回 `421 Misdirected Request`，日志大量 `Invalid Host header: open.linglong.wiki`。Cloudflare Tunnel 转发请求到 `127.0.0.1:9900`，但 Host header 保留为 `open.linglong.wiki`，FastMCP 默认 DNS rebinding 防护只允许 localhost。

**方案**：服务器 `.scout.yml` 的 `mcp:` 段添加 `allowed_hosts: ["open.linglong.wiki", "127.0.0.1", "127.0.0.1:9900"]`，重启容器后恢复正常（421→401 认证拦截）。
