# 2026-07-21 · 自动早报 RSS Top 15 分组修复

## 概览

- 今天 18 个 RSS 源全部成功，共采集 391 条，但自动生成日志显示 `391→15`。
- 早报虽然结构完整，但输入被错误压缩，存在后续内容不足风险。

## 根因

- 自动调度直接使用采集结果：来源位于顶层 `source`。
- 手工回放使用 Redis 标准化数据：来源位于 `extra.feed_name`。
- `_denormalize()` 只识别后一种格式，自动调度时所有来源名变为空字符串。
- `_cap_per_source()` 因而把全部 RSS 当成一个来源，只留下 15 条。

## 修复

- RSS 来源优先读取 `extra.feed_name`，缺失时回退顶层 `source`。
- GitHub 的 stars/growth/period 同时兼容标准化和扁平格式。
- 新增扁平格式、标准化格式及跨来源独立限流测试。

## 验证

- Ruff 通过。
- Agent + 配置一致性测试 53 个通过。

## 学术前沿增加论文日期

- 现状核查发现 RSS 发布时间在采集阶段未保留，模型无法可靠判断论文是否最新。
- 采集优先读取 `published_parsed`、其次 `updated_parsed`，统一保存为 `YYYY-MM-DD`。
- raw 存储和 LLM 输入完整传递 `published`，学术前沿表格增加“日期”列。
- 日期缺失时留空，不允许模型推测。
- 采集、存储、Agent、配置一致性共 78 个测试通过。
