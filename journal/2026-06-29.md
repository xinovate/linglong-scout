## 1. 早报渲染到博客

**问题**:早报 markdown 只存在 Redis(25h TTL)/对话消费,用户想在博客站阅读,复用 Fluid 主题样式,且不污染归档。

**方案**:服务端独立渲染器,零侵入(不碰 scout 代码/镜像、不改 hexo 构建链、不动 nginx、不动 MCP 入口):
- `/opt/scout-render/`:`render.py` + `templates/{daily,index}.html` + `bin/render-brief.sh` + venv(markdown 库)+ archive
- 数据流:`docker exec linglong-redis redis-cli GET scout:brief:<date>:default` → python markdown→HTML → 套 Fluid 模板 → `/var/www/daily/ai/<date>.html` + `index.html`(汇总)
- CSS 复用:链 `/css/main.css` + 内容包 `<div class="markdown-body">` + 模板静态注入 Fluid light 主题 `:root` 变量(变量本由 color-schema.js 运行时注入,静态页跑不了)
- 运行时:宿主机 `/usr/bin/python3.11` venv(Redis 6379 未发布到宿主,只能 docker exec 取);cron 07:20/07:35(早报 07:00 生成后)

**关键坑**:
- Fluid `.markdown-body table th/td` 只设 `border-color`、不设 `border-width`(完整主题靠 bootstrap `.table` class 补,markdown 转 table 不带),极简页表格无边框看不见 → 模板自补 `border:1px solid` + thead 底色 + 斑马纹
- Redis 25h TTL,历史早报不可回填,归档从部署日(2026-06-29)起积累;raw md 私有备份在 `/opt/scout-render/archive/`

**结论**:页面跑通(www.linglong.wiki/daily/ai/2026-06-29.html),cron 自动生成。详见 memory `scout-blog-render`。

## 2. 跨天去重 bug 修复

**问题**:检查早报重复发现 Redis `scout:history:*` 去重库空,跨天去重机制完全失效;板块间也有重复(xAI/DSpark/GPT-5.6 同事件在关键人物+行业要闻+Top5)。

**根因**:`brief_history.parse_sections` 按 `## ` 标题切分,但 `morning_brief.md` 规定各板块用 `### ` 三级标题。`"### 关键人物".startswith("## ")` 为 False → sections 解析为空 → `agent.py:331 if sections:` 不通过 → save 从不执行 → 跨天去重无效。测试盲区:`test_brief_history.py` 样本用 `## `(和 parser 一致),测试一直过却没覆盖真实 `### ` 输出。

**方案**:
- `parse_sections` 标题匹配改为正则 `^(#{2,3})\s+(.+)$`,兼容 `## `/`### `
- 测试样本 `_SAMPLE_OUTPUT` 对齐真实 `### `,补 `## ` 兼容测试 + save/load 回归测试(`test_real_format_parses_and_saves`)
- prompt 加跨板块去重约束 + 学术前沿近7天时效(防 2025 旧论文充数)

**结论**:本地 158 测试全过。待 push 部署后验证 `scout:history:*` 开始累积(commit 5bf198f)。
