# 2026-07-28 · 早报评测基线与时效过滤

## 概览

- 为稳定运行的早报建立第一版确定性评测，不新增通用评测平台。
- 使用 2026-07-28 缓存早报和同日原始输入完成首个真实基线。
- 基线发现来源污染和过期内容两个问题；本次只修复可确定处理的时效问题。

### 任务一：建立评测基线并部署

- 问题：稳定早报缺少可复现的能力边界测试，Prompt 时效约束也未可靠执行。
- 方案：增加历史回放与 8 项确定性检查，并将可判定的 7 天窗口前移到输入过滤。
- 结论：首版功能已于提交 `5362108` 部署，生产健康检查通过。

### 任务二：固定 CI 工具版本

- 问题：CI 无上限安装 Ruff，在 0.16.0 发布后触发 55 个历史规则告警。
- 方案：固定为本次本地验证使用的 0.15.14，并修复新增评测文件的两处 0.16 兼容告警。
- 结论：避免 lint 门禁随工具发布无意漂移；规则升级应单独评估和处理。

## 真实基线

输入为 360 条 RSS 和 16 条 GitHub 数据：

- 七个板块、格式、数量、Top 5、跨板块重复和 GitHub 日榜通过。
- 2 条论文链接不在当日原始输入。
- 1 条政策来源早于 7 天窗口。

此前公开早报中出现过其中一篇论文的相同 ID、不同 URL，近期历史可能向模型提供了题目线索；目前只记录为待复现的 Bad Case，不认定完整根因。

## 时效修复

Prompt 已要求只保留近 7 天内容，但模型仍选入过期政策。处理改为输入侧确定性约束：

- 可解析日期早于窗口或晚于目标日期的 RSS 条目直接排除。
- 无日期或日期无法解析的条目保留，避免误删。
- 同日 360 条 RSS 过滤后保留 254 条，过期政策不再进入 Prompt。

这次只验证输入变化与代码回归。部署后需要用同一日期重新生成，确认最终时效检查转为通过。
