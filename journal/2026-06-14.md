## 任务详情

### 任务 1：系统 code review

**背景**：项目作为 vibe coding 磨刀石（90%+ Claude 写），需要系统评估代码质量。

**结论**：架构判断力强（分层清晰、retry 区分异常类型、config 双重检查锁、三 hook 工程纪律），但暴露 5 类 AI 写 Python 的高频盲区，这些是语义/运行时问题，ruff 静态检查查不出：

1. **async 边界**：`async def run` 内直接调同步 `store_raw`（Redis+文件 IO），阻塞事件循环
2. **连接生命周期**：`get_redis()` 每次新建连接池，慢泄漏
3. **安全比较**：token 用 `==` 非 `secrets.compare_digest`，时序攻击风险
4. **SSRF 校验**：只查字面 host 不解析 DNS，可被 DNS rebinding 绕过
5. **错误可见性**：`except Exception: pass` 满天飞，故障不可见

**核心洞察**：vibe coding 的关键不是"会不会写"，而是"该在什么时候不信 AI、亲手接管"。越资深越容易在 AI 代码上偷懒，因为输出"读得懂、结构也对"。

### 任务 2：python-claude-spec 规范仓库

**目标**：把 hrdt-cloud 的 AI 协作原则 + linglong-scout 的 Python 工程规约抽成可复用规范，任何 Python 项目一键安装。

**三层分层模型**：
- **Layer 0**（语言无关）：AI 协作原则（编码前思考/简洁优先/外科手术修改/目标导向）—— 来自 hrdt-cloud
- **Layer 1**（Python 共享）：01-code-style（含 async 边界红线 + 连接生命周期红线）/ 02-testing / 03-security（含恒定时间比较 + 真实 SSRF）/ 04-error-handling（含错误可见性红线）/ 05-behavior-redlines + python-reviewer agent + ruff hook + testing-patterns skill
- **Layer 2**（项目特化）：每个项目自己填

**5 类盲区焊进规范**：既是 rules 红线，也是 python-reviewer agent 的必查项，详见 `docs/checklist.md`。

**分发机制**：模板仓库 + 幂等 install 脚本（`--update` 只刷 core 保留 Layer 2）。不用 submodule（Claude Code 只认项目根 `.claude/`）也不用 plugin（覆盖不全）。

**仓库**：https://github.com/xinovate/python-claude-spec（公有）
