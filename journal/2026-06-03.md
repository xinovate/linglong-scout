### 1 doc-check pre-push 阻塞模式

**问题**：doc-check 只在 commit 时做提醒（exit 0），push 时无检查。代码改了但文档没同步的情况可以轻松推上去。

**方案**：
- `doc-check.py` 新增 `--pre-push` 模式：用 `git diff origin/main...HEAD` 获取待推送文件
- `--pre-push` 模式下发现文档未更新时 exit 1 阻塞 push，终端红色高亮
- `.githooks/pre-push` 统一执行 journal-check + doc-check --pre-push，任一失败即阻塞

### 4 RSSHub 配置独立化

**问题**：RSSHub 识别靠硬编码 `:1200` 端口字符串，access key 注入依赖这个 hack，切换 RSSHub 实例需逐条改 URL。

**方案**：
- `config.py` 新增 `rsshub_url` 字段
- `collect.py` 删除 `_is_rsshub_url()`，新增 `_resolve_source_url()`：有 `route` 则拼接 `rsshub_url` + 注入 key，有 `url` 则直连
- 5 个 RSSHub 源从完整 URL 改为 `route` 格式（如 `/36kr/newsflashes`）
- 配置文件公开源在上、RSSHub 源在下，注释分隔

### 6 All-in-One Docker Compose 合并

**问题**：Scout/Redis/RSSHub/SearXNG 分散在独立容器中，nginx 反代 SearXNG 做 API Key 认证，维护成本高。

**方案**：
- 4 个服务合并到同一个 `docker-compose.yml`，Docker 内部网络 `scout-net` 互通
- Scout 从 `network_mode: host` 切换到端口映射（仅 `127.0.0.1:9900`）
- Redis/RSSHub/SearXNG 不暴露端口，外部不可达，网络隔离替代 nginx 认证
- 服务器迁移：备份 Redis 数据 → 停旧容器 → 更新 `.scout.yml` URL 为 Docker 服务名 → 启动新 compose
- 容器名统一 `linglong-` 前缀（linglong-scout/redis/rsshub/searxng）
- 删除 nginx SearXNG 反代配置

### 9 HTTP 模式强制鉴权 + init 命令

**问题**：HTTP 模式下 `auth_token` 为空时不挂载中间件，服务器裸奔；本地开发者配了 Redis 但没配 token 也会被锁死（中间件挂载但 `_validate_token` 返回 False）。

**方案**：
- `__main__.py`：HTTP 模式启动时检查 `auth_token`，无 token 则 `SystemExit(1)` 拒绝启动，提示 `linglong-scout init`
- `cli.py`：新增 `init` 命令，生成 `ll-scout:<getpass.getuser()>:<uuid4[:18]>` 写入 `.env`
- `config.py`：`_load_yaml_to_config` 前先 `load_dotenv(override=False)`，`.env` 变量自动注入 `${}` 引用
- 中间件挂载条件从 `auth_token or redis_url` 改为仅 `auth_token`，`redis_url` 只做验证后端
- Docker healthcheck 从 HTTP GET 改为 TCP socket 检测（避免 401）
- `.scout.example.yml` host 默认值从 `127.0.0.1` 改为 `0.0.0.0`（Docker 部署必须）

**问题**：公司动态 25 条 + 应用落地 14 条，占早报近一半篇幅，维度边界模糊导致 LLM 重复归类；单事件（如 Build 2026）洪泛单一维度。

**方案**：
- 公司动态 + 应用落地合并为"行业要闻"，消除最大重叠源
- 精选优先级：行业级事件 > 战略级动作 > 标杆级新品 > 已发布可用产品 > 渐进式更新
- 上限 12 条，每家公司不超过 2 条，同一事件多项发布合并
- 超出条目以注释行列在末尾（`> 本日另有 N 条动态：...`）
- GitHub 趋势采集量从 5/3/3 调整为 4/2/2
- prompt 格式要求段同步更新（7→6 工具表）
