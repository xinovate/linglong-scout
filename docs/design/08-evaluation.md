# D-08 早报评测

> 用固定历史输入检查早报结构、来源、时效、重复和 GitHub 日榜，防止模型、Prompt 与数据处理变更造成静默退化。

## 边界

第一版只做确定性回归检查，不建设通用评测平台，也不把模型评审分数当作事实。内容重要性、解读质量和实际阅读价值仍由人工抽验。

评测对象是完整生成链：

```text
数据源 → 采集与裁剪 → 去重 → Prompt → 模型 → 输出
```

同一历史输入只有在日期、快照、历史、偏好、Prompt 和模型参数固定后，才具备可比性。`IngestAgent.run_from_raw()` 支持注入 `target_date`，构造 Agent 时可注入固定公司快照；评测时不连接 Redis 或外部服务。

## 硬规则

| 检查 | 说明 |
|---|---|
| 必需板块 | 七个板块完整出现 |
| 输出格式 | 表格、无序列表和有序列表符合 Prompt 约定 |
| 数量上限 | 行业要闻不超过 12 条，论文不超过 8 篇 |
| Top 5 | ①—⑤ 五项完整 |
| 来源 | Markdown 链接必须来自当日固定原始输入；比较时忽略 `www`、片段及 `f` / `utm_*` 跟踪参数 |
| 时效 | 有发布日期的来源必须位于目标日期前 7 天内 |
| 跨板块重复 | Top 5 外不重复使用同一来源链接 |
| GitHub 日榜 | 只取日增长，按增长量降序取前 8 个 |

## 使用

准备已生成的早报 Markdown 和对应冷存储原始 JSON：

```bash
python -m linglong.scout.evaluation \
  --brief /tmp/brief.md \
  --date 2026-06-04 \
  --raw-dir ~/linglong/data/raw
```

命令输出 JSON 报告；全部检查通过返回 `0`，任一检查失败返回 `1`。

本地目前只有 3 天完整历史原始输入，先作为真实基线。后续模型、Prompt、数据源、裁剪或去重逻辑变更时运行全量回归；真实事故日期补入回归集。

## 工具链稳定性

CI 固定使用 Ruff 0.15.14，避免无上限升级使新增规则未经评估直接进入门禁。后续升级 Ruff 时，应单独运行全库检查、处理或明确忽略新增规则，再更新固定版本；评测器本身仍尽量兼容新版本的无语义改写规则。
